## 8 · The news timer's timeout (one drop-in) — `palestine-v2-news.service` has `TimeoutStartSec=900`

A classifier version bump re-reads the whole corpus (33.6 k claims, ~12–15 min with the 1.8.0 place reader); the
5-minute timer starts that re-read itself and systemd kills it at 15 min, the transaction rolls back, and the next
tick starts over. Tonight I killed the timer's run and ran the re-read by hand (that is the 18:04 UTC ntfy alert you
got). The lock now makes concurrent runs harmless; the timeout still needs to be an hour:

```
sudo mkdir -p /etc/systemd/system/palestine-v2-news.service.d
printf '[Service]\nTimeoutStartSec=3600\n' | sudo tee /etc/systemd/system/palestine-v2-news.service.d/timeout.conf
sudo systemctl daemon-reload
systemctl show palestine-v2-news.service -p TimeoutStartUSec     # → 1h
```
